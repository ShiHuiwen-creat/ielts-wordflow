# IELTS WordFlow 产品设计规格

## 1. 产品概述

IELTS WordFlow 是一款面向雅思 6–6.5 分备考者的开源背单词 PWA。产品以手机端为主要使用场景，通过“认识 / 模糊 / 不认识”三档反馈和间隔重复机制，帮助用户完成每日新词学习与旧词复习。

首版完全在浏览器中运行，不要求注册或登录，不依赖后端服务。用户可将应用安装到手机桌面，并在离线状态下继续学习。

## 2. 目标与成功标准

### 2.1 产品目标

- 提供一条无需配置即可开始的雅思核心词汇学习路径。
- 让用户每天在一个清晰的学习队列中完成新词与复习词。
- 用可解释的间隔重复规则降低遗忘率。
- 保障学习数据由用户掌控，可本地备份和恢复。
- 以结构清晰、许可证明确的仓库形式发布到 GitHub，便于社区贡献。

### 2.2 首版成功标准

- 用户首次打开后可在 1 分钟内设定每日目标并开始学习。
- 用户完成一次学习反馈后，系统能持久保存进度并正确安排下次复习。
- 刷新、关闭浏览器或离线使用不会丢失已保存的学习记录。
- 用户能查看今日任务、累计掌握、连续学习天数和近期学习量。
- 用户能导出完整备份，并能从合法备份恢复数据。
- 手机宽度 360px 及以上可完成全部核心操作，桌面端布局不溢出。

## 3. 用户与范围

### 3.1 目标用户

主要用户是目标雅思总分 6–6.5、希望以中文辅助理解英语词汇的自学者。首版默认界面为简体中文，学习内容包含英文单词、音标、词性、中文释义、英文例句和例句翻译。

### 3.2 首版包含

- 首次使用引导和每日新词目标设置（10、20 或 30）。
- 雅思 6–6.5 核心词库。
- 今日新词与到期复习词的自动组队。
- 单词卡回忆、答案揭示和三档反馈。
- 基于浏览器语音合成的英式发音。
- 词库浏览、搜索和学习状态筛选。
- 今日与累计学习统计。
- 每日目标、发音等基础设置。
- 本地数据持久化、版本迁移、JSON 导出和导入。
- PWA 安装与离线访问。
- 中英文 README、MIT 许可证、贡献指南、数据来源说明和 GitHub Actions。
- GitHub Pages 部署配置。

### 3.3 首版不包含

- 账号、登录、多设备云同步或服务器端数据库。
- 微信小程序或原生移动应用。
- 社交排名、好友、付费功能或广告。
- AI 对话、作文批改、听力或阅读课程。
- 拼写默写和选择题闯关模式。

## 4. 核心用户流程

### 4.1 首次使用

1. 用户阅读两页以内的功能说明。
2. 用户选择每日新词目标：10、20 或 30，默认 20。
3. 系统初始化本地数据并进入今日页。
4. 用户点击“开始学习”进入当天队列。

### 4.2 每日学习

1. 今日页显示新词数、待复习数、连续学习天数和总掌握进度。
2. 队列优先安排到期复习词，再加入不超过每日目标的新词。
3. 单词卡首先只显示英文单词和发音按钮。
4. 用户点击“查看答案”后看到音标、词性、中文释义、英文例句和翻译。
5. 用户必须选择“不认识 / 模糊 / 认识”之一，系统保存结果并显示下一张。
6. 当天队列完成后，系统展示本轮数量、三档反馈分布和下一次待复习提示。

### 4.3 数据备份

1. 用户在设置页点击“导出数据”，下载包含数据版本、设置、词汇进度和每日统计的 JSON 文件。
2. 用户选择 JSON 文件导入时，系统先完成结构与版本校验。
3. 校验通过后，界面展示摘要并要求用户确认覆盖。
4. 校验失败或用户取消时，现有数据保持不变。

## 5. 信息架构与界面

底部导航包含五个入口：今日、学习、词库、统计、设置。

- **今日页：** 今日任务卡、连续学习、累计掌握和主行动按钮。
- **学习页：** 沉浸式单词卡、进度指示、发音、答案和三档反馈。
- **词库页：** 搜索、全部/未学习/学习中/已掌握筛选和词条详情。
- **统计页：** 今日完成量、近 7 天学习量、累计反馈分布和掌握进度。
- **设置页：** 每日新词目标、自动发音、数据导入导出、重置入口和关于信息。

视觉采用温和纸张色背景、深绿色主色和高对比度卡片。交互元素的触控目标不小于 44×44px；正文对比度达到 WCAG AA；反馈不能只依赖颜色表达。桌面端限制内容最大宽度，不把手机布局简单拉伸到全屏。

## 6. 技术架构

### 6.1 技术栈

- React 19 与 TypeScript 5。
- Vite 7 负责开发与构建。
- React Router 提供客户端路由。
- Dexie 封装 IndexedDB。
- `vite-plugin-pwa` 生成 Web App Manifest 和 Service Worker。
- Vitest、Testing Library 和 `fake-indexeddb` 负责单元与组件测试。
- Playwright 负责一条核心移动端端到端流程。

### 6.2 模块边界

- `src/features/vocabulary`：词汇类型、词库数据读取、搜索和筛选。
- `src/features/scheduler`：纯函数形式的复习计划计算，不依赖 UI 或数据库。
- `src/features/study-session`：今日队列生成和会话状态。
- `src/features/progress`：连续学习、统计聚合和掌握状态。
- `src/lib/storage`：Dexie 表、仓库接口、模式迁移和备份恢复。
- `src/lib/speech`：浏览器语音合成能力检测和英式发音。
- `src/pages`：五个顶级页面和首次使用引导。
- `src/components`：导航、按钮、进度和空状态等共享展示组件。

业务逻辑通过类型明确的函数和仓库接口与界面连接。复习算法与队列生成保持为无副作用的纯函数，以便独立验证。

## 7. 数据模型

### 7.1 词汇

每个词条至少包含：

- `id`: 稳定字符串标识。
- `word`: 英文单词或词组。
- `phonetic`: 音标。
- `partOfSpeech`: 词性。
- `definitionZh`: 中文释义。
- `example`: 英文例句。
- `exampleZh`: 例句翻译。
- `tags`: 主题标签。
- `level`: 固定为 `ielts-6-6.5`。

### 7.2 学习进度

每个已接触词条保存：首次学习时间、最近复习时间、下次到期时间、当前阶段、连续成功次数、总复习次数、最近反馈和是否已掌握。日期以 ISO 8601 字符串持久化，计算时转换为时间对象。

### 7.3 设置与每日统计

设置保存每日新词目标、自动发音和引导完成状态。每日统计按本地日期键保存新学数量、复习数量和三档反馈计数。

数据库从版本 1 开始，未来版本通过显式迁移升级；应用更新不得静默丢弃旧版本数据。

## 8. 间隔重复与队列规则

### 8.1 反馈规则

- **不认识：** 阶段重置为 0；当天尚有队列时在至少 10 张卡后再次出现；下次正式复习为次日。
- **模糊：** 阶段最多增加 1；正式复习间隔依次为 1、3、7、14 天。
- **认识：** 阶段增加 1；正式复习间隔依次为 1、3、7、14、30 天，之后保持 30 天。

连续两次“认识”且阶段达到 4 时标记为已掌握。已掌握单词仍按计划复习；任意一次“不认识”会取消掌握状态。

### 8.2 今日队列

- 先按到期时间升序加入所有已到期词。
- 再从从未学习的词中按词库顺序加入每日目标数量。
- 同一词在正式队列中只出现一次；“不认识”的当天重现由会话模块追加。
- 当天新增词额度按首次接触计算，重复打开应用不会重复发放额度。
- 用户可以在待复习词为零时仍完成当天新词；没有任何任务时显示明确空状态。

## 9. 本地存储、备份与隐私

IndexedDB 是学习数据的唯一权威来源，`localStorage` 仅可用于非关键界面偏好。写入失败时，界面显示可恢复错误并保留当前卡片，不进入下一张。

导出格式包含 `schemaVersion`、`exportedAt`、`settings`、`progress` 和 `dailyStats`。导入校验字段类型、词条 ID、日期格式、数值范围和支持的版本。导入采用事务覆盖，任何一步失败都回滚。

应用不收集遥测、账号信息或个人身份数据。README 明确说明浏览器清理站点数据会删除本地进度，并建议定期导出备份。

## 10. 词库与许可

词库不得复制商业教材或未经授权的题库。首版词条由项目独立整理，单词选择可参考公开的通用英语频率与学术词汇资料，但释义、例句和翻译必须是原创、公共领域或兼容许可证内容。

每批词条都要通过模式校验、重复检测和字段完整性测试。`DATA_SOURCES.md` 记录选择依据、内容作者和适用许可证。首个可用版本至少包含 300 个经过审校的核心词条；仓库结构允许后续按批次扩充。

代码以 MIT 许可证发布。词库若包含不同授权内容，应在 `DATA_SOURCES.md` 和数据文件头部单独标明，不自动视为 MIT。

## 11. 离线、兼容性与异常处理

- 首次成功加载后缓存应用外壳和随包词库；离线时全部核心学习功能可用。
- 支持当前及前一个主要版本的 Chrome、Safari、Edge 和 Firefox。
- 浏览器不支持语音合成或无英式语音时，隐藏或禁用发音按钮并提供文字提示。
- IndexedDB 不可用时展示阻断页，解释原因与浏览器设置建议。
- 找不到词条、空队列、损坏备份和不受支持的备份版本都有独立的用户提示。
- 全局错误边界提供重新加载入口，但不自动清除用户数据。

## 12. 测试与质量门槛

- 复习算法测试覆盖三档反馈、阶段边界、掌握与取消掌握、日期跨越。
- 队列测试覆盖到期优先、每日额度、防重复和当天重现。
- 存储测试覆盖首次初始化、升级、事务写入、导出、合法导入和非法导入不覆盖。
- 组件测试覆盖首次引导、查看答案前不可反馈、三档反馈和空状态。
- Playwright 使用 390×844 视口完成“设置目标 → 学习一词 → 刷新 → 进度仍存在”的核心流程。
- `npm test`、`npm run typecheck`、`npm run lint` 和 `npm run build` 必须通过。
- GitHub Actions 在拉取请求和主分支推送时执行上述质量检查。

## 13. 开源仓库与发布

仓库名称建议为 `ielts-wordflow`，默认分支为 `main`。仓库包含：

- 中英文 README 与本地开发说明。
- `LICENSE`（MIT）、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md` 和 `DATA_SOURCES.md`。
- Issue 与 Pull Request 模板。
- 自动测试工作流和 GitHub Pages 发布工作流。

GitHub Pages 使用仓库子路径构建，Vite 的 `base` 与 PWA scope 均配置为 `/ielts-wordflow/`。若最终仓库名改变，发布前必须同步修改这两个值。

## 14. 交付阶段

1. 建立项目骨架、质量工具和核心类型。
2. 通过测试驱动实现复习算法、队列与本地存储。
3. 实现引导、今日页和完整学习流程。
4. 实现词库、统计、设置和备份恢复。
5. 加入至少 300 个审校词条、PWA、离线能力和开源文档。
6. 完成自动测试、移动端视觉验收、生产构建和 GitHub 发布。

## 15. 验收定义

只有在以下条件全部满足时，首版才算完成：

- 规格中“首版包含”的每项功能均可在生产构建中使用。
- 至少 300 个合法授权且字段完整的词条随应用提供。
- 自动测试和构建质量门槛全部通过。
- 核心流程在目标移动端视口通过自动化和人工视觉检查。
- 项目文档可让新贡献者从零完成安装、测试和构建。
- 公开 GitHub 仓库可访问，源码已推送，GitHub Pages 工作流已配置。
